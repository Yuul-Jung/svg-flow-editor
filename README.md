# SVG Flow Editor v4.0

기존 [html-editor/svg-flow-editor](https://github.com/Yuul-Jung/html-editor/tree/main/svg-flow-editor)의 작동 소스를 별도 저장소로 복제한 개선 버전입니다. 기존 저장소는 수정하지 않습니다.

## 사용

- 브라우저에서 `index.html` 열기
- 구조화 도면의 도형 선택 후 방향키 이동 (Shift+방향키: 1px)
- 연결선 선택 후 꺾임점 핸들 드래그
- 연결선 속성에서 **수동 꺾임 초기화 · 자동 경로 복귀**
- 도형 선택 후 **Ctrl+D** 복제 (선택 집합 내부의 연결선도 복제)
- 실행 취소/다시 실행 시 존재하는 선택 개체 유지

## 검증 상태

- GitHub 파일 업로드와 정적 코드 확인 완료
- 실제 브라우저 상호작용, JSON 왕복, 다중 페이지 및 기존 기능 회귀 테스트는 **미검증**
- 꺾임점별 독립 좌표 저장, 자동 저장/복구, 충돌 탐지, 페이지별 이력은 후속 구현 대상

## 개발 원칙

- 기존 성공 버전 보존
- 실물 브라우저 검증과 정적 검증을 구분
- SoC 교육용 도면의 실제 입출력·누적 동작과 도면 정합성 별도 검증

**검증 구분:** GitHub 소스 반영 및 정적 코드 확인. 실제 브라우저 조작과 JSON 저장·재불러오기 왕복 테스트는 아직 미완료.


## 제2부 01~10장 다중 페이지 자료 (2026-11-08)

- 편집기: [GitHub Pages](https://yuul-jung.github.io/svg-flow-editor/)
- 파일: `chapters/P2_01_pages.json` ~ `chapters/P2_10_pages.json`
- **10개 장 × 2페이지 = 20페이지**: 1페이지 주요 UART/CPU 제어 흐름, 2페이지 장별 기능 상세·독립 RTL/AXI 동작 구분
- `chapters/P2_02.json` ~ `P2_10.json`: 이전 단일 페이지 데이터도 보존하여 호환 가능
- 01장은 기존 내장 `baseScene()`도 보존하되, 상단의 **01장 열기**로 신규 2페이지 자료 선택 가능
- 오른쪽/하단의 파란 **페이지 연결 노드**는 수업자료 페이지 이동만 나타내며, C/RTL 알고리즘의 제어 흐름이 아님
- 화면의 1/2 페이지 선택·다음/이전, 페이지 추가·이름 변경·JSON 작업 저장·불러오기 사용

### 확인 범위

- 정적 확인: 10개 파일 JSON 구조, 20페이지 노드·간선 참조, 페이지 이동 대상, 캔버스 경계·노드 중복 검사
- 설계 및 C/RTL 대응은 일부 검토되었으나 모든 장의 RTL 시뮬레이션, Vivado 합성·타이밍, Basys3 실물 검증과 별개
- 각 페이지의 `DESIGN_DRAFT_NOT_CODE_VERIFIED` 표시는 실제 검증 통과를 뜻하지 않음
- 모바일 브라우저 조작과 Pages 배포 표시의 실시간 재현은 별도로 확인 필요

**원본:** 02~10장 단일 JSON 및 제2부 02장 2페이지 자료는 `Yuul-Jung/html-editor` 저장소에서 보존·이관한 자료이며, 새 저장소에서 적용한 기능 상세 도면은 교육용 설계 개념입니다.


## 내부 여백 공통 기준 및 수동 저장 제외 정책 (2026-11-08)

- **기본값/지원 최소값**: 좌우 `6px`, 상하 `4px`.
- **일괄 적용 범위**: 저장소에서 관리하는 자동 제작 도면 `chapters/P2_01_pages.json` ~ `P2_10_pages.json`(20페이지, 153노드), 호환용 `P2_02.json` ~ `P2_10.json`(9개), 편집기 기본 예제, 새 노드 프리셋, 일괄 편집 초기값.
- **제외 범위**: 사용자가 직접 저장한 JSON/SVG/PNG, 브라우저 임시 복구본, 수동으로 설정한 개별 도형의 사용자 지정 여백. 별도 승인 없이 열거나 덮어쓰지 않음.
- **운영 방식**: 이미 6px/4px를 충족한 자동 도면은 불필요하게 재저장하지 않음. 사용자가 직접 저장한 파일을 편집기에 불러오면 해당 파일의 `pad` 및 `padY` 값을 그대로 사용하고 자동 최소화하지 않음. 사용자가 명시적으로 프리셋 적용 또는 일괄 편집을 수행할 때에만 수정.
- **검증 기준**: 기존 좌표·연결선·노드 ID 및 RTL/C 계약 보존. JSON 구조 검사와 실제 브라우저 표시 검증은 별도 구분.

현재 저장소 자동 제작 도면은 해당 기준을 충족하며, 사용자가 따로 보관하는 수동 저장 파일은 점검·변경 대상이 아닙니다.


## 제2부 01~10장 JSON 캔버스 바깥 여백 일괄 정리 (2026-11-08)

- **수정 대상:** `chapters/P2_01_pages.json` ~ `P2_10_pages.json` 10개(20페이지), 호환용 `P2_02.json` ~ `P2_10.json` 9개.
- **내부 여백:** 좌우 `6px`, 상하 `4px` 유지.
- **캔버스 외부 여백:** 도형 및 제목 경계, 수동 경유점, 자동 반복선의 여유 공간을 계산해 왼쪽/위 약 `24px`, 오른쪽/아래 약 `30px`로 맞춤. 연결선의 자동 경로와 화살촉·문자표시 여유를 고려한 설계값으로, SVG 실제 픽셀 경계의 1:1 보증은 아님.
- **보존:** 노드 ID·제목·설명·크기·간선의 출발점/도착점·분기 라벨·페이지 연결 대상, 모든 노드의 상대 위치. 이동한 도형에 종속된 `via`/`bendPoints`/`laneX` 좌표도 동일한 양만큼 이동.
- **예외:** 01장 제목 위치가 기존 캔버스 왼쪽 경계를 벗어나 있어 첫 페이지 폭은 오히려 증가함. 의도적인 잘림을 허용하지 않고 온전한 출력 영역을 우선함.
- **정적 확인:** 20페이지에서 노드·간선 ID 및 상대 위치/설명 불변, 20페이지 및 레거시 9개 도면에서 도형·제목·계산 연결 경로의 캔버스 경계 초과 없음. 기존 입력/출력 코드나 RTL/Vivado 프로젝트는 변경하지 않음.
- **별도 검증:** 모바일 화면 하단의 빈 편집 영역은 JSON이 아닌 CSS 영역 높이와 화면 확대율의 영향을 받으므로 이번 수정의 검증 완료 대상이 아님.
- **수동 저장본:** 사용자 외부 파일이나 브라우저 임시 저장 내용은 덮어쓰지 않음.

## 제2부 01~10장 상자 글자 맞춤 일괄 적용 (2026-11-08)

이전 `pad=6`, `padY=4` 설정만으로 상자 외형(`w`, `h`)이 실제로 줄어들지 않는 문제를 수정했다.

- 대상: `P2_01_pages.json` ~ `P2_10_pages.json`(20페이지·153노드), `P2_02.json` ~ `P2_10.json`(9개 구형 호환 도면).
- 본문·보조 글자의 실제 내용과 기존 글자 크기를 기준으로 상자 `w`/`h`를 축소했다. 제목·설명 문자열과 글자 크기 자체는 바꾸지 않았다.
- 내부 여백 최솟값 6px/4px을 유지하고, 글자 폭의 보수적 추정치 및 줄간격을 고려해 잘림 방지용 여유를 추가했다. 자동맞춤을 수행하는 노드 유형에 페이지 이동 노드도 포함한다.
- 이동한 노드의 연결선은 끝점에 따라 재계산한다. 관통이 발견된 분기의 경유 좌표는 별도로 조정한다.
- 도면 캔버스 폭/높이는 축소된 노드를 기준으로 다시 계산했다.
- 편집기 도면 품질 검사에서 실제 SVG `getBBox()`로 글자 경계 초과 여부를 추가 검사한다(마름모 글자는 별도 축소 표시이므로 검사 제외).
- 검사 구분: JSON 구문·노드/연결선/캔버스·글자 폭 추정 검사는 정적 검증이다. 폰트 렌더링의 최종 적합성은 GitHub Pages를 열어 **도면 품질 검사**를 실행해서 확인한다.
- 기존 C/RTL 파일, 기존 하드웨어 성공 프로젝트 및 프로그램 명령 내용은 수정하지 않았다.


## 제2부 01~10장 화살표 길이·간격 조화 (2026-11-08)

- 상자 내부 여백 `pad=6`/ `padY=4`, 상자 폭·높이와 원래 글자 크기 **그대로 보존**.
- 20페이지에서 좁아진 상자 크기에 맞춰 상하 행 간격·분기 상자 좌우 거리를 조정했다. 연결선은 도형 포트에 부착되어 좌표 변경을 따라가도록 유지.
- 02장 2페이지의 DISP OFF 분기는 왼쪽, 잘못된 명령 분기는 오른쪽에 배치하여 긴 복귀선 두 개를 양쪽으로 분산했다. 정상/오류 처리 의미는 바꾸지 않았다.
- 하단의 파란 페이지 이동 노드는 프로그램 실행 흐름과 분리된 상태로 유지하며, 빈 도면 너비만 늘리지 않도록 가까이 배치했다.
- 수정 전 기준 `4841b2be`와 비교한 **20페이지의 연결선 정적 직교 경로 길이 합**: `51,736 → 35,672` 도면 좌표 단위(약 **31% 감소**). 02장 상세 페이지는 `5,488 → 3,028`(약 **45% 감소**). 실제 픽셀·브라우저 렌더링 길이를 의미하지 않는다.
- 20페이지 및 기존 단일 JSON 9개의 노드·제목·간선 참조·페이지 이동 대상, 캔버스 경계·상자 간 겹침·다른 상자 관통·서로 다른 연결선의 직교 교차를 정적으로 검사했다. **발견된 오류 0건**.
- C/RTL 코드, Vivado/Vitis 프로젝트, 수동 저장 파일은 수정하지 않았다. 브라우저별 글자·화살표 최종 렌더링과 조작 시험은 별도 확인한다.
